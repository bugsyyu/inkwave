## 0. 一句话和设计原则

**她的雅思课，一天一关：课程包里的每一步变成舞台上的一道门，门上的题就是老师的原题，答对门开，墨涂开一条路；一周打一次 HULLBREAKER，就是周考。关卡只是外壳——题目、判分、记忆模型、估分和她在 IELTS-Base 里的一模一样，证据是同一份。**

设计原则（冲突时按这个顺序）：

1. **好玩的都是真的。** 每一个机制都对应课程里的一个元素；没有数据变化就没有动画；没有不通向学习的操作（DESIGN §2 第 4 条）。本文 §1 的矩阵是检验：课程里的每一种步都在表里，表里每一行都指向一个真实的机制。
2. **内容不减少，任务不堆积。** 一天的关 = 这一天课程包里的步，一步一门，门里的题全是这一步的条目（25 个词就是 25 题，复习日 48 个音标、150 张卡照旧）；一天的分钟数就是课程自己的 `m` 之和（§3 的表，`tests` 核 ±20%）。做不成机制的那一小部分（入门小测、周报生成、口语评分、打卡备注）留在「经典页」入口里，不删、不藏（§1.3）。
3. **证据就是内容。** 关卡里的每一次「当天首答」经 `store.recordFirst` 写进 `ev-<周一>`，同一个 `Model.memory` 算到期；第二次答只是练习（EXAM §1.2「当天首答」）。到期的条目排在道具赛最前面的检查点（A 的 `raceLevel`），错过的条目在当天「回炉门」换一种形式再见一次（§2.6 夯实）。
4. **不惩罚。** 没有连胜断签、倒计时失败、红叉、扣星（EXAM §1.5）。答错是珊瑚色的柔光和「差一点」，门最多卡两次就开；星星只会涨不会掉；机器人先到了就是「没关系」。
5. **iPhone 先行。** 一根摇杆走路（或在小地图上点下一道门自动走），答题是一个游戏动作——点射题物、换道游进车道、踩着拍子跳上台、在游戏键盘上打字开火（PLAY §3）；不要求双摇杆瞄准（`touch.js` 的 fire / jump / squid / sub / special 按钮在学习关里只剩 jump 和 special = 用道具）。热区 ≥ 44 pt；**世界从不暂停、她从不定身、没有盖住画面的面板**（PLAY §0、§1 第 1 条）。
6. **每一句英文都配中文。** 展板、题干、选项、「为什么」都走 `engine.js` 的 `prompt / judge`（已全中文）；舞台里 INKWAVE 自己的英文牌子不管。
7. **只用 INKWAVE 自己的东西。** 舞台是 `config.js` `OFFLINE_MAPS` 的 7 张（`cargo` 只联机、没有机器人、不能打 Boss，不用）；道具是 `SUBS` / `SPECIALS` 换皮（§2.4）；人物是程序生成的 squidkid，动作只用 `character.js` 的 `trigger` / `setDance`（§5）；音效只用 `docs/CONTRACTS.md` §2 的名字；HUD 只用 `hud.banner / feed / judge` 的种类。不加任何新素材。
8. **数据驱动，可扩展。** 每一天的表由课程包的步按规则生成（§6.2），第 4 周起老师的新课程包一导入就有关卡，不用重新设计；新题型（表格、地图、配对、拼句）按 §4 的名单加机制即可。

四个名词（全文统一）：**门**（gate：有题、要答的一步）、**路标**（sign：只看不答的一步——写字墙、回声亭、打卡垫、周报牌、入门小测牌）、**锁**（lock：一道门上的一题；25 个词的门有 25 把锁，每 5 把开一截）、**展板**（board：门前的学习内容——音标的口型 tip 和例词、单词的音标和中文、语法的讲解行、阅读的课文）。

## 2. 四种形式的玩法细则

共用的东西先说清楚：

- **一天 = 一局。** 选周、选天、选形式 → 进舞台 → 一门一门 → 出口 → 结算。一天的门就是课程包这一天的步（`DAY_PLAN[w][d].gates`），顺序照课程 a → b → c；路标在出口区。任何一天都可以用三种形式里的任何一种玩（推荐的只是排第一），Boss 是整周的，另算。
- **学习在前，题在后。** 带展板的门（音标、单词、语法、阅读）先给展板（M6 展板路：舞台上立着的牌子，走到跟前镜头框住它），她看完（走过、听完）才出题；展板上没有计时：跑酷的看板段墨潮和机器人一起慢下来（0.25 倍），对抗赛的备战里区域的钟和倒数顶住、机器人站着（§2.2、§2.3）。这是 EXAM §1.5 的「没有倒计时」。
- **世界不停。** 题是舞台上的题物（PLAY §3：墨靶、墨幕车道、节拍台、字弹、弱点、翻牌靶），出题时她照样能走、镜头弹簧过渡去框住题物，没有 `match.paused`、没有 `learn.hold`、没有面板；解谜里没有敌人；跑酷里机器人照游（它们的延迟就是公平）；对抗赛里区域倒数照走；Boss 只在她答完之后才出招（出题时它的大脑冷却被顶住，这一段的钟陪着等）。
- **一题的生命**：出题（`engine.prompt`，tts 自动放一遍）→ 作答 → `engine.judge` → 对错 + 中文「为什么」→ 首答 `store.recordFirst`（返回 `first:false` 的就是练习）→ 效果（§2.7 的表）→ 下一把锁。
- **回炉**：第一次答错，立刻换个问法再问一次（§2.6）；第二次还错，给答案和「为什么」，锁照开，条目进当天的回炉队列；出口前的**回炉门**把队列里的每一个换一种形式再问一次。
- **手机**：走路一根摇杆，或者小地图上点下一道门 → 沿 `G.nav` 自动走（用机器人的寻路，B 的提案 §6.4）；题干是顶上一条细细的题条（`ui/play-strip.js`，只吃自己按钮上的触摸），答案在舞台里点（PLAY §6.1）；打字时游戏自己画的键盘在下面（M4）；`jump` 还在（过水、上台阶），`special` 键 = 用手里的道具；`fire / squid / sub` 在学习关里隐藏。

### 2.1 解密闯关 `puzzle`（一个人、没有敌人、没有钟）

- **目标**：从己方出生点走到对面出生点（出口），路上每一道门都开了。
- **舞台和一天**：`DAY_PLAN` 定（§3）：第 1 周白天，第 2 周傍晚，第 3 周隔天交替；舞台按当天主题选（w1d2 数字和价钱 → 十字市场，w2d1 交通 → 电车，w3d4 旅行 → 渡轮…），每周 7 张都用一次。舞台用 turf 的版本（`onlyIn: 'zones'` 的几何只在对抗赛里）。
- **门怎么放**（flow.js 跑在 `G.nav` 上，规则是数据 `RULES.puzzle.place`）：
  1. 路线 = `G.nav` 上从 `spawnPads[0]` 到 `spawnPads[1]` 的 A*（1 m 网格，走 / 跳上 / 跳下的边；`wet` 越高代价越大，所以路线自然避开水边）。
  2. 每道门有一个 `spot`（§3 的表里的 layout tag + 在哪一半）：取那个 tag 的方块在那一半的实例，找离它最近、且在路线 25 m 内的 nav 节点；找不到就用 `at`（0..1 的路线分数）处的节点。
  3. 节点要求：`wet === 0`（离开阔水 ≥ 2.2 m）、不在出生区（`node.zone < 0`）、相邻两门沿路 ≥ 10 m、门前走廊宽 ≥ 3 m（左右各 1.5 m 内有 nav 节点）、门和下一门之间的路线不经过「只有鱿鱼能过」的缝（halyard 的水缝、kelpline 的二层）——不满足就沿路线向后挪到第一个满足的节点。
  4. 门 = 一道灰色墨幕横在走廊上（`curtain` 的 prop，宽 = 走廊宽，灰色不属于任何队），前面 3 m 是触发圈（`gate.trigger`）；展板立在门前 6 m 的路边（`word-board` 5 块排成一排，各 1.2 m 宽）。
  5. 路标在出口区：对面出生点前的那块地（§3 表里的「出口区」tag），写字墙贴着墙，回声亭是一个 `curtain` 围出来的小亭，打卡垫就是对面的出生垫（`decor.pulse`）。回炉门在出口区入口（`at: 0.9`）。
- **题 → 效果**：

| 事 | 发生什么 | 声 / 动 |
|---|---|---|
| 答对 | 锁开一截（门上的墨幕掉一块）；门全开时墨幕炸成她的墨（`fx.explosion`），门后走廊 `paint.flood` 成她的颜色（鱿鱼可以游，11.8 m/s）；HUD feed「答对了」+ 为什么 | `splat_big`；squidkid `trigger('jump')` 小跳 |
| 答错（第 1 次） | 门上的锁亮珊瑚色柔光；「差一点」+ 为什么；同一题换问法再来（§2.6） | `ui_back`（柔）；角色不动，不抖、不闪 |
| 答错（第 2 次） | 给答案和为什么；锁照开（门不会永远卡住）；条目进回炉队列 | `ui_toggle` |
| 连对 3 | 发型发光（`AnimState.special = 1`），手里多一个道具（§2.4：解谜里只有墨雨、回声） | `special_ready` |
| 连对 5 | 1.5 秒 `victory` 舞 + 横幅「连对 5 题！」 | `level_up` |
| 一道门开 | 门前地面 `fx.ring`，走廊涂开 | `refill_full` |
| 走到出口（打卡垫） | `victory` 舞，`results_win`，结算卡：首答对几题、回炉清了几个、星几颗、明天几点到期（`thenWait` 第二版） | `victory_fanfare` |

- **机器人**：没有。
- **失败 / 重来**：没有失败。中途退出，已答的首答都记了，下次从第一道没开的门继续（本机记 `gate` 进度；门的开合不是证据）。
- **计分和星**：首答正确率（`firstRight / scored`）和回炉清零（§2.8）。
- **解锁**：前一天「走完」（每道门开过、每个路标看过）就开下一天——不看分数（宿主的 `dayDone` 也只看「做了」）。

### 2.2 道具赛 `race`（一个人 + 3 个机器人、同一条路线、检查点、钟）

- **目标**：按检查点顺序跑完一圈，比机器人先回到终点；每个检查点一道门的题。学习的分量不变：到期的条目排在最前面的检查点（A 的 `raceLevel`）。
- **路线**：环线——出生点 → 己方一条道 → 中场 → 对面一条道（镜像）→ 中场另一侧 → 另一条道回到出生点；检查点沿环线按 `at` 均匀放。§3 表里的 `spot` 和解谜是同一份（出发 → 中场 → 对面）：道具赛里 flow.js 把标「（对面）」的 spot 解析到**回程那条道上的镜像实例**，终点是己方出生垫而不是对面的出口——所以表里写的位置名在两种形式里都对，只是环线把「对面」折回来了。复习日的环线是整张舞台的一整圈（§3.1）。
- **一个检查点 = 墨浪跑酷的一段路**（PLAY §5.2，形式 id 还是 `race`，中文名「墨浪跑酷」）：**看板段**（M6 展板沿路立着，墨潮和机器人一起慢到 0.25 倍，她游过哪块镜头框哪块）→ **题行**（一行一个条目：墨幕车道 M2 / 拍子上换道 M3，她游进哪条道就是答哪个；单词卡、听写句、写句在**滑行段**上打字开火 M4）。她一直在游，没有「到门停下答题」；机器人照 `BOT_ANSWER` 掷骰子、按检查点算名次。
- **题 → 效果**：

| 事 | 发生什么 |
|---|---|
| 答对 | 门开、路涂开；掉一个道具（§2.4 `PROP_DROP.race`：每答对 1 题掉 1 个，最多拿 3 个）；feed「答对了」 |
| 答错（第 1 次） | 换问法再来（钟照走） |
| 答错（第 2 次） | 给答案；**走远路**：墨道把她带进旁边一条绕远的支路，约 `detour` 秒后汇回主路（没有支路的地方就在主路上把墨潮放慢 `detour` 秒）——不原地定住；条目进回炉；拿着护盾就不绕 |
| 连对 3 | 护盾（下一次错不绕路） |
| 连对 5 | 墨道（到下一检查点的路全涂成她的墨，游过去） |
| 机器人先到终点 | feed「机器人先到了，没关系」；她照跑到终点，首答照记，星按学习算（§2.8），名次只给一个奖杯（本机，不是证据） |
| 她先到 | `victory_fanfare` + 舞 |

- **机器人**：`BOTS_OF.race` 3 个，用 `BOT_NAMES`，同一条路线；它们在每个门前按 `BOT_ANSWER[difficulty]` 掷骰子：对的概率 `correct`，延迟 `delay` 秒（均匀），错了走同样的绕路；头上冒一个 ✓ / ✗ 的气泡（squidkid 的 `trigger('jump')` / 站着不动）。它们永远看不见她的题。橡皮筋：机器人每领先她一个检查点，延迟 + `rubber` 秒（最多 `rubberCap` 个），设置里写明「机器人会等你」。难度用 INKWAVE 自己的 `DIFFICULTY` 三档（Chill / Fresh / Fierce = 轻松 / 正常 / 激烈）：轻松 55% · 6–10 s，正常 70% · 4–7 s，激烈 85% · 2.5–4.5 s。机器人也会用道具（`propUse`）：墨幕挡她 3 秒、墨弹停她 3 秒——都只影响名次，不影响题。
- **钟**：显示的是圈时间，没有「时间到」；HUD 的 `one_minute` / `times_up` 不用。

### 2.3 对抗赛 `duel`（她 + 3 个队友机器人 对 4 个机器人，Zone Control）

- **目标**：一道门 = 一轮区域争夺；答题就是蓄墨：答对一题，区域里最缺墨的一块（`zonePlan` 的 need）泼成她的颜色；谁先把倒数数到 0 谁赢这一轮。一天 = 门数那么多轮；轮和轮之间是**备战**（比赛不停：区域的钟和倒数顶住、机器人站着不打，下一步的 M6 展板一块一块立在她面前，squidkid 摆 `lobby_pose`；往前走 `LEARN.duel.prepWalk`（6 m）、按回车或点题条上的「开始这一轮」就开打）。
- **舞台**：用 zones 版本的几何（`layout.zones`，`onlyIn: 'zones'` 的梯子、台阶都在；7 张都有区域定义 `zones-data.js`）。一轮只用**中央区域**（不轮转：对抗赛每一轮新建一个 `ZoneControl`，`final = true`、`nextSwap = ∞`，所以没有轮换也没有「最后 30 秒」的横幅），时间 = 这道门的分钟数夹在 `LEARN.duel.roundMin/roundMax`（60–300 秒）之间——课程的分钟是学的时间，抢区域的一轮要短；她答完题轮就结束，不必等；倒数到 0 也是一轮的结束，不是局的结束（道具赛 / 对抗赛的局没有「时间到」）。**钟到 0 或区域倒数数完时她正在答一题，这一轮等她答完**（play-9：最多 `LEARN.duel.graceS` 8 s，打字题 `graceTypeS` 25 s；钟上写「最后一题」、对面的「答题」骰子停；输赢按钟到 / 数完那一刻算，这期间的击倒除外；等不到就把这题放回队首、下一轮再问，不记证据）。
- **她的作答**：

| 事 | 发生什么 |
|---|---|
| 答对 | 区域里最缺的那块 `paint.flood` 半径 2.5 m（连对每加 0.5 m，最多 4.5 m）；特殊槽 + 15；`splat_big`、`trigger('shoot')` |
| 答错 | 不掉墨、不扣分（不惩罚）；换问法再来；第 2 次错进回炉 |
| 连对 3 | 特殊槽满（`special_ready`）：她按 special 用一个道具（墨雨 = 下一题提示；回声 = 再听一遍；护盾 = 下一次错不让对面得「答题」） |
| 连对 5 | 1 秒舞 |

- **机器人**：队友 3 个照 INKWAVE 的 zones 脑子（`ZonePlan` 的 paint / guard / watch / push）正常打——**不答题**（`alliesAnswer: false`，所以她的题就是她队的全部「蓄墨」）；对面 4 个照常打，另外每 `duelCadence` 秒（轻松 9、正常 6、激烈 4）掷一次「答题」骰子，对了在区域里泼 `duelFlood` m 的墨（相当于她答对一题）。两边都是真的 zones 规则（占 80% 拿区域、40% 中和、倒数、罚分），只是她这边的墨主要来自答题；她也可以拿摇杆走到区域里站着（站在自己的墨上更快充特殊）。
- **区域的声音、横幅、倒数**都是 `zones.js` 自己的（`zone_*` 音效、`zones:*` 事件），本文不重复。
- **一轮的结算**：`hud.judge` 两边的区域百分比；**星和证据只看题**（§2.8），输赢只给奖杯。

### 2.5 Boss 战 `boss`（周考：HULLBREAKER）

- **规则照 EXAM §2.3**：复习日的课走完后的第二天起开放，10 天窗口；一天推荐一段（顺序 L → R → W → S，上一段没打完先接着打）；四段都打完给四科估分（第二版，§6.4 提案 4）。想一口气打完也可以。
- **Boss = 四段 HP**（`bossPlan`）：

| 段 | HP | 题 | 题池 | Boss 阶段（BOSS.md） | 分钟 |
|---|---|---|---|---|---|
| L 听力 | 100% → 66% | 20：本周音标门、发音小测、听辨岔路、听写池的条目按 30 弱 / 30 到期 / 40 新学配，隔天交错 | ≈ 130 | 1：`slam`、`barrage` | 14 |
| R 阅读 · 词汇 · 语法 | 66% → 33% | 20：单词、语法、阅读的条目 | ≈ 215 | 2：`sweep`、`charge`、`crablets` | 14 |
| W 写作 | 33% → 10% | 1 题 = 本周写字墙里的 3 句（消息的 3 个要点，`WT` 逐句判） | 30–36 | 3：`frenzy`，壳裂、肚子露出来 | 10 |
| S 口语 | 10% → 0% | 1 组 = 本周回声亭的 4 问 + 朗读 2 句听写句；「说完了」就是最后一击 | 7 | 3 | 6 |

- **题 → 效果**：答对 = 一次弱点命中（`hit_marker`，×2.5 的弱点特效），打掉这一段 HP 的 1/20（W 段 3 句各打掉这一段的三分之一——流程逐句判、逐句掉血，`bossPlan` 仍把它算一题；S 段 6 张卡各打掉最后 10% 的六分之一，「说完了」就是一击）；每段有时间预算（`LEARN.boss.phaseTime`，14 / 14 / 10 / 6 分钟，只在 Boss 动的时候走，她答题时停）——到了就「这一段的时间到了，剩下的留到另一天」，Boss 落到这一段的底、下一段开始；答错 = Boss 出一招（这一阶段的招，有 ≥ 0.6 s 的预告），她用摇杆躲 3 秒，然后下一题——她的 HP 不计分，被泼中只是 5.5 秒重生；连对 3 特殊槽满，连对 5 Boss 眩晕一次（`stun: true`，肚子亮）。
- **play-9 更正**（LEARN §28）：出题时 Boss 不出招但照样走路、转身；她点射弱点上的球，那一颗墨弹每帧朝那个球修正（跟着走动的 Boss、射程外也补上重力），第一发就中——整局第一发打空 0 次（play-8 整局 56 次出题里 7 次）。
- **小队**：她 + 3 个机器人（BOSS.md 的 squad 行为：散开、打它、躲预告、清蟹崽），只有她答题；机器人的输出只是演出，Boss 的 HP 只被题打动。
- **舞台**：`BOSS_STAGE[w]`（w1 海滨广场、w2 盐田、w3 山城，都 dusk；`mapBossOk` 全过），不和复习日同一张。
- **满月月考**：`week.n % 4 === 0` 的周 `month: true`：同样四段，结算卡多「这四周」一页（经典页）。
- **Boss 自己的东西**（吼、脚步、预告、受击、阶段、音乐）全是 `boss*.js` / `bossAudio.js` 的；本文只定「什么时候打它、打多少」。段的时长（14 / 14 / 10 / 6 分钟）要进 `config.js` 的 `LEARN.boss.phaseTime`（§6.4 提案 3）。

### 2.6 答错以后（夯实；`RETRY`）

1. **当场换问法**（不是证据，`store` 返回 `first:false`）：选择题重排选项并给中文；打字题给提示（这时就等于 `H`）；听辨两个词都放一遍、放慢；写句子给缺的关键形式。
2. **第 2 次还错**：给答案和「为什么」，锁照开，条目进回炉队列（`relearn`）。
3. **回炉门**（出口区入口，`at: 0.9`，不占课程分钟）：队列里每个条目换一种形式再问一次——`RETRY.later`：单词门错的 → 卡片打字；卡片打字错的 → 单词门；音标门 → 先给口型 tip 和例词再问；语法门 / 发音小测 → 先给讲解板那一行；听写 → 逐词慢放再写；阅读 → 先给中文再问；听辨 → 两个词都放再走；写句 → 给参考句的中文和关键形式再写。最多 12 个，多的留给明天。
4. **明天**：记忆模型把它算成到期 → 道具赛第一个检查点（A 的 `raceLevel`）、今日小考的到期份额、第 2 周起课程自己的「开场抽查」。

### 2.8 计分、星、解锁（`STARS`、`UNLOCK`）

- **分**：结算卡写真实的「首答对几题 / 共几题」和「回炉清了几个」；不写分数段、不写百分数记忆（EXAM §1.5）。
- **星**（一天一组，本机记，只涨不掉）：★ 走完（每道门开过、每个路标看过）；★★ 首答 ≥ 80%；★★★ 首答 ≥ 95% 且回炉清零。道具赛的名次、对抗赛的输赢、Boss 的用时只给一个奖杯图标，不进星。
- **解锁**：第 d 天走完开第 d+1 天；第 7 天走完开下一周；Boss 在第 7 天走完后的第二天开；任何开了的天、任何形式随时重玩（首答才是证据）。没有「出关分数」——宿主的 `dayDone` 也只看做没做；出关标准是按阶段的（第 6 周的出关小测是老师的课）。

### 3.1 复习日（第 7 天）的特别设计

复习日「只复习、不学新内容」，课程本身就是一周里最满的一天（EXAM §2.2），所以：
- **形式固定是道具赛**，路线是舞台的**一整圈**（环线：两条道都跑），3 个机器人同跑；没有看板段（没有新内容），钟一直走——这是一周里唯一「像比赛」的一天，复习就该快。
- **48 个音标总复习**：音标门 12 截（每 4 一锁），没有展板；答错的音标回炉时才给口型 tip。
- **150 个单词总复习**：快闪翻牌（看中文想英文 → 翻面 → 认识 / 不熟），10 张一锁；点「不熟」的当场打字一次（`T/H`），再进回炉。40 分钟 150 张 = 每张 16 秒，和宿主的卡片自测一个节奏。自评进证据是 `F` 方式（§6.4 提案 1，G 已做：`store.recordFirst` 的 `how`）。
- **听辨大挑战** 10 个岔口连着跑；**语法综合小测** 10 题一锁一题。
- **第 2、3 周的复习日**多了开场抽查 8 个、连读 / 重音总复习 8 题、听写综合 8 句、一篇阅读、写 6 句（上周写错的再写一遍——课程自己的夯实）。
- **终点**是入门小测牌（w1）、周报牌、回声亭：都是路标；今日小考不出；结算卡上一句预告「这一周走完了。明天起，Boss（周考）一天一段。」
- 复习日的分钟还是课程的（195 / 210）；星照 §2.8。

### 6.2 每日表的生成规则（`buildDay`；以后的周照它来）

1. 读这一天课程包的步（`daySteps`）；`type ∈ {write, speak, checkin, weekly, placement}` 的是路标，其余是门，顺序照 a → b → c。
2. 每道门：`mechanic = mechanicOf(step)`（§1.1 的映射，`grammar` 看 `k`，`flash` 看条目数 > 60 → 快闪翻牌），`ask = 条目数`（全问），`batch = MECHANICS[mechanic].batch`，`minutes = step.m`，`at = (i + 1) / (门数 + 1)`，`spot = SPOTS[stage][round(at × (spots − 1))]`（夹在第 2 和倒数第 2 个之间）。
3. 路标：`at = 0.95`，`spot` = 最后一个（出口区），`ask` 只有写字墙有。
4. `minutes = Σ step.m`；`form / stage / time` 查 `DAYS[w][d]`（第 1–3 周的手排表）。**第 4 周起**没有手排表，`dayPlanFor(week, d)` 按同样的规则从导入的课程包现算（已实现，测试用 w1 的内容冒充 w4 核过）：`form` 按 `d % 3` 轮 puzzle → race → duel、复习日（第 7 天或带 `weekly` 步的那天）race；`stage = STAGE_IDS[(n × 7 + d) % 7]`（一周 7 张各一次）；`time` 按周的奇偶；`planDay` 对任何已加载的周都能用。`extras.quiz` 第 1–6 天有、复习日没有。节奏模型（§6.3）的「复习日更快」看的是第 7 天，课程包要是把复习日放在别的天，分钟自检会偏，关卡表不受影响。
5. Boss：`bossLevel(week)` 的门按 `phase` 进四个池，`pick` 按 30 / 30 / 40 选、按天铺开、同类不相邻（`interleave`）；W 取 3 句，S 取 4 问 + 2 句朗读。

### 6.3 节奏模型（`PACE`，只用来核分钟）
