## 0. 一条规矩

**题就是舞台上的一个东西，答就是一个游戏动作。** 题 = 舞台里出现的「题物」（墨靶、墨幕车道、节拍台、待打的字靶、Boss 的弱点）+ 一声英文 + 屏幕顶上一条细细的题条；答 = 射中它、游过它、踩着拍子跳上它、把字一个个打成墨弹射上去。**世界从不暂停**：没有 `match.paused`、没有 `match.learn.hold`、没有盖住画面的面板。答对，题物炸成她的墨、门开、加速、跳舞；答错，题物变珊瑚色、挂一把锁、题条上写「差一点」和正确答案，然后换一种玩法再来一次。

课程的内容、判分、记忆模型、证据一点不动——变的只是外壳从「卡片」换成「玩法」。

## 1. 硬约束（不变量，实现和评审都按它核）

1. **不暂停、不定身、不弹面板。** 开关 `LEARN.play` 打开时：学习局里任何时候 `match.paused === false`（她自己按暂停除外）、`match.learn.hold` 不存在或为假、没有显示出来的 `.iw-learn__panel`（这个元素一直在 DOM 里——`hud-learn.js` 建一次、用 CSS 藏；play-1 更正）。题条（§2）是唯一的新 DOM，它不吃题条按钮以外的触摸。验收脚本（§10）就查这三样。
2. **判分只有一条路。** 一个动作最后只产出两种答案之一：**选项序号**（射中第几个靶、游进第几条道、跳上第几块台）或**一串字**（打出来的词 / 句）。都交给 `engine.judge`（gen.js `Gen.check` / 宿主 `Host.dictScore` / `WT`），然后 `store.recordFirst`（当天首答）。不新写判分，不加证据方式（`vendor/ielts/model.js` 的 `MODES` 只有 L F R T H D1 D2 D3 P W S K，vendor 文件不改）。
3. **证据如实。** 每种玩法记什么方式写死在 §4 的表里，测试核。特别是：
   - **打字的不能变成选字母。** 单词卡（900 个）是 `T`，`model.js` 第 636 / 691 行把「错过以后又**打对**」当成单独的证据（`src === 'T'`）。所以单词照打字，键盘是武器（§3 M4）。从一堆字母里挑着拼 = 看了提示 = `H`，只在她按「提示」或回炉时用。
   - **打字时提交前不给对错。** 每按一个键射出一颗墨弹、在靶上写出那个字母，但字母一律是中性的灰墨，不变绿不变红；按「射」（回车）才判。中途给对错就是提示，按规矩得记 `H`。
   - 「我的写法也对」照旧记 `S`；复习日翻牌的自评照旧记 `F`；听写句照旧记 `L` 带百分数；写句照旧 `W`。
4. **节奏不等于对错。** 节拍玩法（§3 M3）里，**选哪块台 / 哪条道才是答案**；踩没踩在拍子上只影响加速、舞蹈和星星，绝不让一个选对的答案记成错。整小节没有任何操作 = 没答：这一题过一小节重放一次，再没动作就排到这一段最后，**不写证据**。
5. **没有误答。** 只有「有意的」动作才算答：
   - 射击：只有**点在题物上**（点射，§6.1）或**准星压在题物上时开的火**、而且是**直接命中**，才算选它。溅射、流弹、对抗赛里打敌人时扫到的墨都不算。
   - 跑酷：题一出来时，她所在的位置在**两条道中间的分隔线上**（墨道把她轻轻推到中线），不动就穿过中间的空隙；穿过空隙 = 没答（同第 4 条：重来一次，不写证据），不是错。
6. **不惩罚。** 错 = 珊瑚色 + 一把锁 + 「差一点」+ 正确答案和「为什么」+ 换玩法再问（LEVELS §2.6 的回炉照旧）。没有扣血、没有失败、没有「时间到」（双人联机赛 `versus2` 的答题时限是联机规矩，照旧）。**错不用对方的队色**（LEVELS §5：敌墨让人想到受伤），错是珊瑚色（`#f08a7a` 一类）；跑酷里游进错道是一道珊瑚色的软墨幕，穿过去慢一下（借 `enemyInkDecel` 的手感），不掉血。
7. **每一句英文都配中文**（LEARN §1 第 4 条）：题条、靶上的标签、展板都照 `engine.prompt` 给的中文。
8. **只用 INKWAVE 自己的东西，不加素材文件。** 题物是程序生成的形状，用现成的墨材质 / 墨着色器 / `paint` / `fx`；墨幕用副武器 `curtain`（Drip Curtain）那块幕；台子用出生垫（`decor.pulse`）；人物动作只用 `character.js` 的 `trigger` / `setDance`；声音只用 CONTRACTS §2 的名字；标签用 CanvasTexture 画、字体用 HUD 现有的。不加模型、贴图、音频文件。
9. **画风和流畅度和 INKWAVE 一致。** 同一个渲染器、同一套墨、同一套特效；相机只用 `cameraRig` 的弹簧过渡，不硬切；iPhone `quality=low` 下题物出现前后帧时间不变差（§7 的预算）。
10. **竖屏横屏都能玩**（§8）。跑酷和节拍横屏更好玩，就提示一次「横过来更好玩」，不强制；竖屏照样全能玩。
11. **内容一条不少。** 221 步、2 247 个条目，每一个都有一个玩法（§4），`design.test.mjs` 核 `missing 0`、没有一个条目落到「卡片」。
12. **开关可退。** `LEARN.play`（`config.js`）：`true` 走本文，`false` 回到现在的卡片（第 8 期删卡片之前，出了问题能一键退回）。

## 2. 一题的生命（新）

1. **出题**：舞台上出现这一题的题物（§3），它们在出现前 2 道门就建好（标签图集、网格），出现时只是淡入 + 弹一下，不卡帧。同时：英文 tts（或录音，H 的接法照旧）放一遍；顶上的**题条**出现。
2. **题条**（`ui/play-strip.js`，唯一的新 DOM）：一到两行——中文题干（`prompt` 给的）+ ▶ 再听 +（允许时）「提示」。竖屏在钟下面，横屏在顶部正中；字 ≥ 17 pt，按钮 ≥ 44 pt；`pointer-events` 只开在按钮上。它不是卡片：不盖舞台、不挡题物、不收焦点。
3. **作答**：一个游戏动作（射 / 游 / 跳 / 打字开火），产出选项序号或一串字（§1 第 2 条）。
4. **判**：`engine.judge` → 首答进 `store.recordFirst`。
5. **结果**（`EFFECTS` 照旧挑动作和声音）：
   - 对：题物炸成她的墨（`fx.explosion` + `paint.flood`），门开、墨道往下一道门涂过去；跑酷里加速一小段；节拍踩准了跳舞（`setDance`）。题条闪一下她的墨色再收起。
   - 错：题物变珊瑚色、门上多一把锁；对的那个题物亮出来（标签描边），题条写「差一点：是 ___」+「为什么」第一句，停 `LEARN.ui.verdictMs`；然后换玩法再问（`RETRY.later` 的对照表，§4 最后一列）。第二次还错：给答案，锁照开，进回炉队列（LEVELS §2.6）。
6. **下一题**：同一道门的下一个条目接着出题物——不回到「走」的状态，门前就是一小段连续的「靶场 / 车道 / 舞台」。

## 3. 玩法目录（八种，都用 INKWAVE 现成的东西搭）

### M1 墨靶 `ink-target`（射击：选择题）

- **看起来**：门前浮着 2–4 个墨球（程序生成的球，中性灰墨材质，表面有墨的光泽），每个下面挂一块标签牌（英文 + 中文）。标签长的题（语法 / 发音小测、阅读题，最长 54 个字符）用**横幅靶**：一块宽墨板代替球，最多 3 块。
- **怎么玩**：点一下靶子（§6.1）→ 她转身、用手里的武器射过去 → 墨弹落到靶上那一刻才判（逻辑和画面一起，≤ 0.3 s）。摇杆照样能走、照样能用准星射。
- **复用**：武器和弹道是 `weapons.js` 的 `Projectiles`；命中用 `boss.js` 里现成的「射线对命中球」精确判断；炸开是 `fx.explosion` + `paint.flood`。

### M2 墨幕车道 `lane-curtain`（跑酷：选择题）

- **看起来**：她在自己的墨道上游（鱿鱼形态 `swimSpeed 11.8`，墨道在前面自动涂），前方墨道分成 2–4 条道，每条道尽头一道墨幕（副武器 `curtain` 的幕），幕上写选项。
- **怎么玩**：左右滑 = 换道，上滑 = 跳（`swimJumpVel`），下滑 = 潜（鱿鱼形态）。游进对的幕：幕炸成她的墨、加速一小段（借 `swimSpeed` 加成，不加新物理）；错的幕是珊瑚色的软墨幕，穿过去慢一下（`enemyInkDecel` 的手感，不掉血）。
- **读题时间**：题物在她前方 `D = 速度 × 提前量` 处出现，提前量 = 2.5 s + 每个字 0.06 s，封顶 6 s；题区里墨潮放慢到 0.6 倍（慢，不停）。
- **道够不够宽**：舞台的导航网格每格 1 m，只查过「能站人」，没有宽度。所以题行只放在**横向净宽 ≥ 道数 × 1.5 m** 的路线点上（沿路线法向在网格上扫，纯函数，Node 里用 `src/world/maps.js` 测）；不够宽就少一条道（最少 2 条）；2 条都放不下就往后挪到下一个够宽的点。
- **复用**：游泳、跳、潜、爬墙（墨道遇到能上的墙会涂上墙，她游上去——这就是跑酷）、超级跳的弧线（`special_leap`）当跳台；机器人是道具赛现成的 3 个对手。
- **实现（play-runner，LEARN §20）**：道宽 1.5 m、幕宽 1.0 m，两幕之间 0.5 m 是空隙——每行出现时墨道把她送到离她最近的那条分隔线上，不动就从空隙穿过去（没答）。「净宽」是在导航网格上量的：网格的可走带本来就让开了墙（胶囊 0.46 m），所以要的是**各道的幕都在可走带里** = 道数 × 1.5 − 0.5 m 的网格带（墙到墙就多于道数 × 1.5 m）；扫的时候栏杆（相邻两格没有走路边）、坡和台阶（比路面高 / 低 0.45 m 以上）都算到头。路线先拉直再平滑（A* 的 8 向锯齿平滑以后还是弯的，题行要一段直路）。少一道之前先在 10 m 内往前找放得下全部道的点（几米路不要紧，少一个选项就改了题），再在原处少一道，再往前找，最后才降到两道。横幅行（> 12 英文字符或 > 8 汉字，最多 3 道）在题条里按道列出 A / B / C：390 px 竖屏上 41 个字母的幕要到最后一秒才看得清。游泳的鱿鱼沉在自己颜色的墨里看不见，所以她脚下的墨面上有一个白圈 + 箭头，她对着的那道幕亮一点。

### M3 节拍台 `beat-pads`（劲舞：听辨对子、音标）

> 下面是**已经做出来的样子**（`src/learn/play/beat/`，交付记在 LEARN §21；接进门的流程是下一步）。

- **看起来**：一块舞台——她脚下一块「家」台，四周 2 块（听辨对子，左 / 右）或 4 块（音标，↑ ← → ↓ 一个跳舞毯的十字）发光台，都是出生垫的样子（`decor.js` 的玻璃黑底、池子里慢慢转的墨、发光的边圈 / 虚线轨 / 刻度 / 箭头，自己写的同款着色器，因为 decor 的是私有的），没答之前一律中性的淡紫灰光，池子里是灰墨、中间一个白箭头；每块台外侧立一块标签牌（英文大、中文小，左上角一个小角标「A ↑」「← A」），牌子永远正对镜头。竖屏台子排得窄而深，横屏宽而浅（`pads.js` 两套），镜头按方向各算一个俯视的机位，所有台子、牌子和她都在题条下面的安全带里，牌子上小的那行（中文）在屏幕上 ≥ 17 px（不够就把牌子放大）。
- **拍子**：舞台随 `music.js` 的拍子跳——每一拍所有边圈亮一下（重拍更亮），牌子轻轻一弹。拍子网格和跑酷是同一个约定（`clock.js`：`beatWindow / beatGrid / nearestBeat / onBeat / nextBar / beatPulse`，名字、参数、返回值都一样，合并后可以变成一个文件）：合成的曲子从 `music.current` 拿 bpm 和第一拍、换到游戏时钟上；放的是录音（没有拍速）就用 `LEARN.beat.bpm`（105，解谜的 menu 曲）。窗口 `max(0.15, 0.35 × stepDur)`。
- **怎么玩**：词在**一个小节线**上放出来（离台子升起至少 `LEARN.beat.lead`），**下一小节的重拍**跳（`round.js`）；这一小节里每块答案台上有一圈「逼近环」从外面收到台子边上，正好收在重拍上——看着环就能踩准。答案 = 跳上哪块台：点屏幕（离哪块台的投影近就是哪块：2 块 = 左 / 右半屏，4 块 = 屏幕的上 / 左 / 右 / 下四边）、滑（左右；4 块加上下）、键盘（← → ↑ ↓、A–D、1–4，按选项顺序）。她**真的跳过去**（`trigger('jump')` 起跳、`trigger('land')` 落地，一道弧线，减少动效时低而快）；**落地那一刻才交答案**（逻辑和画面一起），踩没踩准看的是起跳那一刻离重拍多远。词放出来之前点台子不算答（她什么都没听到），台子耸一下。
- **对 / 错**：流程用跳上的台的序号判（`engine.judge` → `store.recordFirst`，台子永远不知道哪个对）。对：那块台涨满她的墨、边圈变她的色、一圈闪光、`fx.explosion` + 台下 `G.paint.splat` 一片她的墨、`splat_big`；踩准了再加 `setDance('victory')` 0.8 s 和台边的连击光（减少动效时不跳舞）；没踩准也照样对，只是没有舞。错：那块台变珊瑚色（池子也带珊瑚）、牌子珊瑚色，对的那块台亮成她的墨、牌子描她的墨，题条写「差一点：是 ___」（play-1 的题条合并前用 `on.say(text, { coral })`），`ui_back`；停 `LEARN.beat.verdictMs`。下一题她先跳回家台。
- **整小节没动**：这一小节过去没有任何跳 → 下一个小节线重放一次词、再给一小节；还没动 → `on.defer()`，流程把这一题排到这一段最后，**不写证据**（测试核：证据是空的）。
- **跑酷里**：同一题是「拍子上换道」（play-runner 的 `lanes.js`，同一套拍子函数）。
  - **实现（play-runner，LEARN §20）**：跑酷里她管不了自己什么时候到（墨潮定速度），能踩拍子的只有换道，所以「拍」落在换道上：拍子行一出现，墨潮调到让她正好在一条小节线上到这一行（0.45–0.85 倍游速），这一题的词在那之前一小节放；决定这一行的那一下换道落在窗口里 = 踩准（更大的加速 + 跳出墨面一个 `victory` 小舞），踩偏了道对照样算对，只是不跳。窗口照写 `max(0.15, 0.35 × stepDur)`——`music.js` 的 `stepDur` 是十六分音符，所以游戏里 84–150 bpm 的曲子都是 ±150 ms（见 LEARN §20「拿不准的」）。录音没有拍子：用 128 bpm 的网格，幕照它脉动。
- **复用**：出生垫的样子和底座网格（decor 的 lathe 轮廓）、`character.js` 的 `trigger` / `setDance`、`fx`、`paint`、CONTRACTS §2 的声音名。每个台 2 个实例（底座 + 面），牌子一个 `InstancedMesh`：整个舞台 3–4 个 draw call。

### M4 字弹 `type-shot`（打字射击：单词卡、听写句、写句）

> 10-16 业主：「最好迅速做一个键盘模型……保留输入时的人物运用该模型武器的动画，直到输入好了就展现出立体的 3d 输出结果在游戏世界里，有真正的游戏性交互效果」。下面是**已经做出来的样子**（`src/learn/play/type/`、`src/ui/play-keys.js`，交付记在 LEARN §19；接进门的流程是下一步）。

- **武器：打字蟹**。她跳进 INKWAVE 的 Crab Rig（`special-props.js` 的 `buildCrab`：壳、六条腿、背上的迫击炮，同一套玩具塑料 + 她的墨），加特林换成一台**蟹钳托着的打字机**：
  - **键盘**：34 颗大键帽（a–z、空格、`' - . , ?`、⌫、射），一个 `InstancedMesh`，字母来自一张字图（Titan One；⌫、射画成图标）。键距 14 cm，跟随镜头下 390 宽的手机上也看得清。按一下：那颗键帽**在同一帧**往下沉、亮成她的队色，弹回来。
  - **字杆扇**：31 根字杆（每个能打出字的键一根）排成半月扇，躺在键盘后面的字杆窝里；按键时那一根甩起来砸在滚筒上，再弹回去。
  - **滚筒和纸**：滚筒上一张纸立在打字机上方（14 格一行、往上卷行），砸下去那一刻纸上出现一个**中性灰**的字（略歪、略深浅，像真打字机），刚打的那个字有一下湿墨的「鼓」；托架带着滚筒和纸一格一格往左走，到行尾（空格在第 9 格以后，或满 14 格）「叮」一声滑回来、纸往上卷一行。⌫ 退一格、那个字往上一飘消失。
  - **墨罐**：打字机侧面一个玻璃墨罐，装她的墨，每打一个字挤一下、墨慢慢变少，下一题加满。
  - **人物**：她坐在舱口里（舱盖拿掉了，不挡键盘），只用 `character.js` 现成的一次性动作：每按一个键 `trigger('shoot')`（手臂往前一顿），按「射」`trigger('throw')`（把纸塞进炮里），答对 `trigger('jump')`；答错没有动作（LEVELS §5）。
- **怎么玩**：屏幕下方是**游戏自己的键盘**（`play-keys.js`，不是系统键盘：iPhone 横屏时系统键盘吃掉半屏、还会自动改字）。竖屏一行 10 个、键约 34 × 50（iOS 的大小），上面一条「打出来的字 + ▶ 再听 + 提示」；横屏三行宽键（约 50 × 44），▶ 和提示放在前两行行首，打出来的字只在世界里的纸上。竖屏占屏幕约 39%，横屏约 44%。实体键盘照样能打（按键在捕获阶段被键盘接走，不会变成走路；Esc 照旧是暂停）；长按 ⌫ 连删。
- **按「射」**：纸从滚筒上撕下来（锯齿边）→ 卷成一个纸弹 → 跳进背后的迫击炮 → 后坐、整台蟹一蹲 → 纸弹沿抛物线飞向靶子（0.75–1.25 s，按距离）→ 落点溅一团**灰墨**。镜头这时弹簧过渡到「墨字」机位，键盘缩下去。
- **3D 墨字**：她打的字在落点长出来：字先画在画布上，按字形采样成 ≤ 上限颗的墨珠（`InstancedMesh`、INKWAVE 的墨材质、一个 draw call），从溅墨处一颗颗弹进字形（从左到右、有过冲）。一行字高 0.62 m；长句先折行、再缩到 4.4 × 1.9 m 里。墨珠上限按画质：low 480、medium 760、high 1000、ultra 1200。**判之前一律中性灰**。
- **判**（流程调 `engine.judge`，结果交给 `resolve`；字弹自己不判）：
  - **对**：墨珠炸开成她的队色（`fx.explosion` 沿字三处、落地的墨珠在地上溅成她的墨 `G.paint.splat`）、`splat_big` + `refill_full`，她跳一下。
  - **错**：字变珊瑚色（`#f08a7a`，不是对方队色），中间往下塌、底下几颗墨拉成滴；正确拼写在它上方用她的墨重新长出来；`ui_back`。「我的写法也对」照旧在题条上（写句记 `S`）。
  - **听写句**：对上的词炸开（比例 ≈ `Host.dictScore` 的百分数），没对上的词留着变珊瑚色；参考句在上方长出来，没听出的那几个词是珊瑚色（`judge` 给的 `toks`）。
  - 「提示」：键盘上的提示键只发 `onHint`，流程照宿主规矩记 `H`、在题条上给音标 / 首字母。
- **提交前不给对错**（§1 第 3 条）：键帽亮的永远是她的队色、纸上的字永远是同一个灰（一个颜色 uniform，没有任何输入能改它），打字蟹和键盘根本拿不到答案——答案只在「射」之后经 `resolve` 进来。`type-rig.test.mjs` 核：同样的按键、不同的答案，每一帧键帽颜色、矩阵、纸上的字一模一样；源码里没有判分的字眼。
- **机位**（`frame.js`，纯函数）：打字时在她右肩后上方、高到她的头低于键盘中间那排、整台打字机和纸都在题条和键盘之间；按「射」后换「墨字」机位（键盘收起，字在屏幕中上、打字机在下沿）。竖 390 × 844、横 844 × 390、桌面 1280 × 720 都框得住。
  - **play-5 更正**（浏览器里量的，LEARN §24）：`frameFor` 假设题条只占屏幕顶上 10 %，真实的题条底边竖屏在 242 / 844（29 %）、横屏在 113 / 390（29 %），纸和横屏的大半台打字机都压在题条下面；横屏它还放宽成「头低于最远那排」；纸跟着托架走（第一个字时纸心在她右边 0.62 m，第 14 个字时在左边 0.62 m），`RIG_POINTS` 只算了居中的纸。对抗赛 / Boss 的字弹改用 `arena/m1.js` 的 `arenaTypeFrame`：取景带 = 题条真实的底边到键盘真实的顶边，纸在整段行程里的四角都在带里、头低于中间那排；宽屏再试题条左右两侧的角落（避开 HUD 顶排），打字机哪里大放哪里（844 × 390 上是左上角，约 120 px 宽——带里只有 100 px）。解谜的 `wire/type.js` 没改（dev 的文件），同样的问题还在。
- **预算**：打字蟹 + 墨字见 LEARN §19 的实测（instancing；每帧不分配；材质用 `compileAsync` 预热，`shot.warm()`）。
- **回炉 / 跑酷 / 联机**：照 §4 的表（回炉 M1 ↔ M4；跑酷「滑行段」；联机的答案还是一串字）——这些接法是接进门的流程时做。

## 5. 五种形式怎么变

### 5.1 解密闯关 `puzzle` → 走 + 射

- 门的位置、路线、自动走都照 B 的 `LearnFlow`。走到门前 `gateRadius`，题物在门前出现，相机弹簧过渡到「框住所有题物」的位置（§6.2），她还能动。一道门的条目一个接一个，门前就是一小段靶场 / 舞台。没有敌人、没有钟。

### 5.2 道具赛 `race` → 墨浪跑酷（形式 id 不改，中文名改「墨浪跑酷」）

- 路线照 `loopRoute`（出去一条道、回来一条道）。她和 3 个机器人在自己的墨道上游，自动向前；她只管换道、跳、潜。检查点 = 一行一行的题（M2 / M3），单词卡和听写句在「滑行段」（M4）。机器人照 `BOT_ANSWER` 掷骰（从来不看她的题），橡皮筋照旧。
- 道具照旧（`leap · rain · echo · shield · curtain · bomb · lane`），但都变成跑酷里的东西：墨幕挡住身后的机器人、墨弹定住最近的机器人、`lane` 是一段直通的墨轨、`leap` 是超级跳弧线、`rain` 是提示（记 `H`）。没有道具能跳过题（LEVELS 照旧）。
- 第二次答错不再「原地定住 `detour` 秒」（那就是定身）：改成**走远路**——墨道把她带进旁边一条绕远的支路，`detour` 秒后汇回主路。有盾就不绕。
- 「看板段」（课文、单词展板）在起跑前和检查点之间的直道上，用 M6 的牌子沿路排开；牌子区墨潮慢下来，机器人也慢下来（公平）。
- **实现（play-runner，LEARN §20；`?learn=w1d3&kind=runner`，race.js 暂时不动）**：一行一个条目，一天 50–68 行，所以要跑很多圈——路线就是道具赛那一圈（`loopRoute`），首尾相接重复；检查点 = 每道门第一行的读题区起点（机器人在那儿照 `BOT_ANSWER` 掷骰子、橡皮筋照旧，`race.js` 的 `_bot` 原样用），终点 = 她最后一行之后的那一圈起点（重答 / 没答多了，终点跟着往后挪，机器人跑同一条线）。走远路：A* 找一条绕开主路的支路（一半以上的节点离路 ≥ 2.2 m、长 ≥ 1.35 × 它跳过的那段），支路上的墨潮让她走 ≈ `detour` 秒后汇回；没有支路的地方（单条通道）就在主路上把墨潮放慢 `detour` 秒。单词卡、听写句、写句在「滑行段」：这一期是标明的占位（不计分），字弹（M4）的接口是 `RunnerFlow.typed`。看板段这一期只做了阅读课文（起跑前读，「出发」）；单词展板、语法讲解行等 M6。道具照用道具赛的（超级跳改成跳过一段路，落在下一行的读题区前面，不跳题）。
- **play-4 更正**（LEARN §23）：开关 `LEARN.play` 下 `FLOWS.race` 就是 `RunnerFlow`（中文名「墨浪跑酷」，关掉照旧卡片版道具赛；`?kind=runner` 留作调试入口）。滑行段计分：打字蟹 + 游戏键盘在路上，墨潮 0.3 倍、机器人同倍数慢；射 → 纸弹打到前方路上，墨字在她游到之前长好、她游过时演判定；判分走 `RunnerFlow._judgeRecord`（车道行和打字同一条，和 `race.js _answer` 写出的证据逐字一样）。看板段：有单词展板 / 音标 / 语法讲解的站，第一行前面一段路上立 1–6 块板（路外 2.6 m、朝她来的方向），墨潮 0.25 倍、机器人同慢，她这一段路对着哪块板镜头就框哪块（约 2.7 s 一块，往前游就是翻页）。路边道具挡住镜头时镜头升起越过它（看穿窗口只在跟随镜头下开，跑酷不用跟随镜头）。

### 5.3 对抗赛 `duel`（含今日小考）→ 区域里的靶场

- 区域照 INKWAVE 的 Zone Control 跑，机器人照打。题物浮在争夺中的区域上空（M1），第一个射中对的靶 = 这一题答对、区域涂一片（`duelFlood`）。她照样能打敌人；打敌人扫到的墨不算答题（§1 第 5 条）。字靶（M4）出现时她脚下自动铺一圈她的墨、敌人的子弹打不到她（小小的护盾，几秒），打完就撤——打字不该被偷袭。
- 小考 8 题照旧是一轮对抗赛。
- **play-5 更正**（LEARN §24）：题簇按屏幕排好（play-1 的 `layoutTargets`），放在朝区域中心的方向、离镜头 `boom + 3…8.5 m`（她射得到的地方，再远标签就太小、墨弹也到不了）、躲开地面和挡视线的东西，然后钉在这个锚点上随相机转（从哪看都是同一排）；她离区域中心超过 `LEARN.arena.askNear`（14 m）时一题最多等 `askWait`（6 s）让她走近——所以多半在区域上空，但她不来也照样出题。字弹的泡泡盾是 Bubble Guard（`specials.giveShield`，4 s、打字时续着、按「射」后剩 0.6 s 就撤），脚下 2.4 m 一圈她的墨。轮与轮之间的备战板（M6 课文）照旧停住比赛——它不在一轮里，PLAY §1 第 1 条的「任何时候」这里没做到，见 LEARN §24 拿不准的。

### 5.5 双人 `versus2` / `coop2` → 同样的题物，房主判

- 两边看到同样的题物；答案照旧是选项序号或一串字，走现在的消息（`versus2.js` / `coop2.js` / `duo.js`），房主判、先对者得。`coop2` 的「一个人拿线索、一个人作答」照旧：线索方听到 / 看到题，作答方的屏幕上才有可射的靶 / 键盘；两块墨垫照旧。
- **play-6 更正**（LEARN §25）：
  - **「同样的题物」= 同样的题，不是同一个位置**：每个屏幕按自己的相机把题簇放在争夺中的区域上空（就是对抗赛的题簇，`ArenaHost`），两边一样的是机制、标签、顺序和对的那个。换问法原来各屏自己抽随机数（干扰项和顺序两边不一样），改成按题号 + 条目 id 播种（`duo.js duoAltPrompt`），`lq` 没加字段。
  - **versus2**：选择题是墨靶，打字是打字蟹 + 脚下墨圈 + 泡泡盾（对抗赛那一套）；墨、墨圈、墨字溅的墨都是她自己队的（访客在 1 队）。答题时限照旧（选择 20 s / 打字 30 s），剩几秒写在题条的小标签上；时间到了题物演「时间到了：是 ___」，不判不写。打字时被打倒，这题还开着，她起来再出。
  - **coop2 的线索方 = 一块展板**（M6 `BoardWalk`）：立在她墨垫前面 1.7 m、朝去门的方向，题干 + 中文 + 怎么做 +「再听」，没有选项、没有输入框；放不下（墙、栏杆挡着取景）就用题条。竖屏的板窄一点（1.3 m，屏上字一样大，镜头不用退到她身后 4 m）。
  - **coop2 的作答方**：任何选择题都是墨靶（M1）——听辨 / 音标在解谜里是节拍台，可节拍台会在小节线上放这个词，作答方不能听到任何东西；打字是打字蟹（M4）。作答方的「提示」不给中文（只说「提示在队友那边」）。
  - **判定两边同时显示**：作答方的题物 / 墨字演对错；线索方的题条写「X答对了」/「差一点」——这题换问法要回到她手里时不写正确答案。

## 6. 手机输入和镜头

### 6.1 点射（触屏的主操作）

- 点屏幕：先在屏幕空间里找题物（每个题物投影的包围框外扩 16 px，有效热区 ≥ 44 pt），点中了 → 她转身（`aimFace*` 弹簧，不瞬转）、朝它开一枪；墨弹落到它身上才判。没点中题物 → 照 INKWAVE 原来的触屏（右半边看；学习关里开火键从 B 起就藏着，没有「射」——play-1 更正）。
- 纯函数 `pickTarget(screenX, screenY, projected[])`，Node 测（重叠时取最近的、边缘外扩、横幅的长方形）。

### 6.2 镜头框住题物

- 题物出现时，`cameraRig` 弹簧过渡到一个能让**所有题物都在安全区里**的位置：安全区 = 屏幕去掉顶上的题条、底下的键盘（M4 时）、两边 16 px。竖屏视野窄，题物排成 2 × 2 或竖着叠；横屏横着排。
- 纯函数 `layoutTargets(n, labels, aspect, safe)` → 每个题物的位置和大小，Node 测（竖 390 × 844、横 844 × 390、iPad 两个方向、标签 54 个字符的横幅）。

### 6.3 跑酷和节拍

- 左右滑换道、上滑跳、下滑潜；横屏时左拇指也可以用摇杆左右推。节拍台：两块时点左 / 右半屏，四块时点四个象限。所有手势的阈值放 `config.js` `TOUCH`。

### 6.4 键盘（M4）

- 见 §3 M4。键盘是游戏画的（DOM，一次建好，按键只改 class），不是系统键盘；不弹系统键盘、不自动改字、不自动大写。外接键盘照样能打（`input.js` 的按键）。

## 7. 画风和流畅（怎么保证和 INKWAVE 一样）

- **形状**：墨球 = 程序生成的二十面体细分球 + 现成的墨材质；横幅 = 圆角墨板；墨幕 = 副武器 `curtain` 的那块幕；台子 = 出生垫；墨船 / 写字墙 = 现成的门 / 墙网格拉长。没有新文件。
- **演出**：对 = `fx.explosion`（她的墨色）+ `paint.flood` + `EFFECTS` 里的声音和动作；错 = 珊瑚色淡入 + 门上的锁标（B 的八面体 `lock`）+ 柔的 `ui_back`；连对照 `EFFECTS` 的横幅和舞。
- **预算**（`quality=low`，iPhone）：一道活跃的门最多多出 12 个 draw call（同类题物用 `InstancedMesh`）；一道门一张标签图集（≤ 1024 × 512 的 CanvasTexture），在**前两道门**时就画好，门开后释放；题物用的材质在关卡加载时预热（`renderer.compileAsync`，照 `texlib.js` / `showcase.js` 现成的做法），游戏中不编译着色器；每帧不分配对象；题条和键盘只在换题时改 DOM。
- **量**：`main.js` 现在只有每半秒一个 `fps` 读数；第 1 期加一个只在 `__inkwave.debug` 下开的帧时间采样（记每帧毫秒数，给 p50 / p95），在同一个舞台上「门前出题」和「普通走路」比，p95 不差过 10%；真机看 TestFlight。

## 8. 横屏

- **游戏页两个方向都支持**。跑酷和节拍横屏更好玩：第一次进这两种玩法时提示一次「横过来更好玩」（不挡、能关、不再提示），竖屏照样全能玩。所有新版式（题条、题物排布、键盘）竖横各有一套，§10 两个方向都截图。
- **App（IELTS-Base 那边）**：现在 `Info.plist` 的 iPhone 只有竖屏。改成：App 其它页照旧锁竖屏，只有游戏页能转——App 的 delegate 实现 `supportedInterfaceOrientationsFor`，当 WebView 的地址是 `/game/index.html` 时返回 `.allButUpsideDown`，否则 `.portrait`；离开游戏页时用 `requestGeometryUpdate` 转回竖屏，并调 `setNeedsUpdateOfSupportedInterfaceOrientations`。`Info.plist` 的 iPhone 方向列表要不要同时加上横屏（有的系统版本只在列表里的方向里选），在第 7 期真机上核。
- **`touch.js`**：学习局两个方向都不出「请转屏」；`PORTRAIT_SCREENS` 和竖屏顶排偏移照旧；「`learn.hold` 时触屏不响应」这条随 `hold` 一起删掉。

## 9. 分期（一次只开一个子代理，一期一期来；每期结束都要绿）

每期结束的「绿」= `npm run check` 绿 + `npm run test:learn` 绿 + §10 的启动核查（这一期涉及的形式 × 竖横两个方向）+ 主会话看过截图。每期一个分支 `play-<n>`，合进 `claude/upbeat-newton-virpn1`；文档在 LEARN.md 记一节「play-n 交付」，DEVLOG 一条。

1. **内核 + 解谜里的选择题。** `LEARN.play` 开关；题物系统（`src/learn/play/`：题物的建立 / 释放、标签图集、`layoutTargets`、`pickTarget`、命中 → 选项序号）；题条；`puzzle` 在开关下不暂停、不定身；选择题（单词选义、语法 / 发音小测、阅读题）走 M1，其它条目暂时还走卡片（只在开关下、只到第 3 期）。纯函数的 Node 测试；启动核查改成「选择题门：没有面板、不暂停、题物在安全区里、点射能答、首答记一次」。
2. **字弹 M4。** 单词卡、听写句、写句在解谜里走 M4；游戏键盘竖横两套；提示 / 「我的写法也对」/ 百分数；回炉 M1 ↔ M4。测：提交前不泄露对错（截图 + 断言字母材质颜色不变）、证据方式和 §4 一致。
3. **节拍台 M3 + 展板路 M6 + 回声亭 M7 + 翻牌靶 M8 + 路标。** 做完解谜里一张卡片都没有。测：拍子窗口纯函数、整小节没动不写证据、踩偏照样算对。
4. **墨浪跑酷。** `race` 换成 §5.2：墨道、换道、跳、潜、爬墙、题行（净宽扫描纯函数）、滑行段、拍子上换道、机器人、道具、走远路。横屏提示。
5. **对抗赛 + 今日小考 + Boss。** §5.3、§5.4。
6. **双人联机赛、双人合作赛。** §5.5，两个客户端实测。
7. **横屏进 App**（IELTS-Base：delegate、`Info.plist`、`WebView.swift`；游戏这边 `touch.js` 竖横逐屏审）。
8. **删卡片。** 开关默认 `true`，卡片的代码路径删掉（留着要用的字符串）；LEVELS / LEARN 改到和本文一致；`design.test` 核每个条目有玩法；同步进 IELTS-Base、发 TestFlight。

**下一版 TestFlight 在第 8 期之后发**：业主说「下一版发布要改成这样」，所以哪种形式还有卡片就不发。
