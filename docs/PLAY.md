## 0. 一条规矩

**题就是舞台上的一个东西，答就是一个游戏动作。** 题 = 舞台里出现的「题物」（墨靶、墨幕车道、节拍台、待打的字靶、Boss 的弱点）+ 一声英文 + 屏幕顶上一条细细的题条；答 = 射中它、游过它、踩着拍子跳上它、把字一个个打成墨弹射上去。**世界从不暂停**：没有 `match.paused`、没有 `match.learn.hold`、没有盖住画面的面板。答对，题物炸成她的墨、门开、加速、跳舞；答错，题物变珊瑚色、挂一把锁、题条上写「差一点」和正确答案，然后换一种玩法再来一次。

课程的内容、判分、记忆模型、证据一点不动——变的只是外壳从「卡片」换成「玩法」。

## 1. 硬约束（不变量，实现和评审都按它核）

1. **不暂停、不定身、不弹面板。** 开关 `LEARN.play` 打开时：学习局里任何时候 `match.paused === false`（她自己按暂停除外）、`match.learn.hold` 不存在或为假、DOM 里没有 `.iw-learn__panel`。题条（§2）是唯一的新 DOM，它不吃题条按钮以外的触摸。验收脚本（§10）就查这三样。
2. **判分只有一条路。** 一个动作最后只产出两种答案之一：**选项序号**（射中第几个靶、游进第几条道、跳上第几块台）或**一串字**（打出来的词 / 句）。都交给 `engine.judge`（gen.js `Gen.check` / 宿主 `Host.dictScore` / `WT`），然后 `store.recordFirst`（当天首答）。不新写判分，不加证据方式（`vendor/ielts/model.js` 的 `MODES` 只有 L F R T H D1 D2 D3 P W S K，vendor 文件不改）。
3. **证据如实。** 每种玩法记什么方式写死在 §4 的表里，测试核。特别是：
   - **打字的不能变成选字母。** 单词卡（900 个）是 `T`，`model.js` 第 636 / 691 行把「错过以后又**打对**」当成单独的证据（`src === 'T'`）。所以单词照打字，键盘是武器（§3 M4）。从一堆字母里挑着拼 = 看了提示 = `H`，只在她按「提示」或回炉时用。
   - **打字时提交前不给对错。** 每按一个键射出一颗墨弹、在靶上写出那个字母，但字母一律是中性的灰墨，不变绿不变红；按「射」（回车）才判。中途给对错就是提示，按规矩得记 `H`。
   - 「我的写法也对」照旧记 `S`；复习日翻牌的自评照旧记 `F`；听写句照旧记 `L` 带百分数；写句照旧 `W`。
4. **节奏不等于对错。** 节拍玩法（§3 M3）里，**选哪块台 / 哪条道才是答案**；踩没踩在拍子上只影响加速、舞蹈和星星，绝不让一个选对的答案记成错。整小节没有任何操作 = 没答：这一题过一小节重放一次，再没动作就排到这一段最后，**不写证据**。
5. **没有误答。** 只有「有意的」动作才算答：
   - 射击：只有**点在题物上**（点射，§6.1）或**准星压在题物上时开的火**、而且是**直接命中**，才算选它。溅射、流弹、对抗赛里打敌人时扫到的墨都不算。
   - 跑酷：题一出来时，她所在的位置在**两条道中间的分隔线上**（墨道把她轻轻推到中线），不动就穿过中间的空隙；穿过空隙 = 没答（同第 4 条：重来一次，不写证据），不是错。
6. **不惩罚。** 错 = 珊瑚色 + 一把锁 + 「差一点」+ 正确答案和「为什么」+ 换玩法再问（LEVELS §2.6 的回炉照旧）。没有扣血、没有失败、没有「时间到」（双人联机赛 `versus2` 的答题时限是联机规矩，照旧）。**错不用对方的队色**（LEVELS §5：敌墨让人想到受伤），错是珊瑚色（`#f08a7a` 一类）；跑酷里游进错道是一道珊瑚色的软墨幕，穿过去慢一下（借 `enemyInkDecel` 的手感），不掉血。
7. **每一句英文都配中文**（LEARN §1 第 4 条）：题条、靶上的标签、展板都照 `engine.prompt` 给的中文。
8. **只用 INKWAVE 自己的东西，不加素材文件。** 题物是程序生成的形状，用现成的墨材质 / 墨着色器 / `paint` / `fx`；墨幕用副武器 `curtain`（Drip Curtain）那块幕；台子用出生垫（`decor.pulse`）；人物动作只用 `character.js` 的 `trigger` / `setDance`；声音只用 CONTRACTS §2 的名字；标签用 CanvasTexture 画、字体用 HUD 现有的。不加模型、贴图、音频文件。
9. **画风和流畅度和 INKWAVE 一致。** 同一个渲染器、同一套墨、同一套特效；相机只用 `cameraRig` 的弹簧过渡，不硬切；iPhone `quality=low` 下题物出现前后帧时间不变差（§7 的预算）。
10. **竖屏横屏都能玩**（§8）。跑酷和节拍横屏更好玩，就提示一次「横过来更好玩」，不强制；竖屏照样全能玩。
11. **内容一条不少。** 221 步、2 247 个条目，每一个都有一个玩法（§4），`design.test.mjs` 核 `missing 0`、没有一个条目落到「卡片」。
12. **开关可退。** `LEARN.play`（`config.js`）：`true` 走本文，`false` 回到现在的卡片（第 8 期删卡片之前，出了问题能一键退回）。

## 2. 一题的生命（新）

1. **出题**：舞台上出现这一题的题物（§3），它们在出现前 2 道门就建好（标签图集、网格），出现时只是淡入 + 弹一下，不卡帧。同时：英文 tts（或录音，H 的接法照旧）放一遍；顶上的**题条**出现。
2. **题条**（`ui/play-strip.js`，唯一的新 DOM）：一到两行——中文题干（`prompt` 给的）+ ▶ 再听 +（允许时）「提示」。竖屏在钟下面，横屏在顶部正中；字 ≥ 17 pt，按钮 ≥ 44 pt；`pointer-events` 只开在按钮上。它不是卡片：不盖舞台、不挡题物、不收焦点。
3. **作答**：一个游戏动作（射 / 游 / 跳 / 打字开火），产出选项序号或一串字（§1 第 2 条）。
4. **判**：`engine.judge` → 首答进 `store.recordFirst`。
5. **结果**（`EFFECTS` 照旧挑动作和声音）：
   - 对：题物炸成她的墨（`fx.explosion` + `paint.flood`），门开、墨道往下一道门涂过去；跑酷里加速一小段；节拍踩准了跳舞（`setDance`）。题条闪一下她的墨色再收起。
   - 错：题物变珊瑚色、门上多一把锁；对的那个题物亮出来（标签描边），题条写「差一点：是 ___」+「为什么」第一句，停 `LEARN.ui.verdictMs`；然后换玩法再问（`RETRY.later` 的对照表，§4 最后一列）。第二次还错：给答案，锁照开，进回炉队列（LEVELS §2.6）。
6. **下一题**：同一道门的下一个条目接着出题物——不回到「走」的状态，门前就是一小段连续的「靶场 / 车道 / 舞台」。

## 3. 玩法目录（八种，都用 INKWAVE 现成的东西搭）

### M1 墨靶 `ink-target`（射击：选择题）

- **看起来**：门前浮着 2–4 个墨球（程序生成的球，中性灰墨材质，表面有墨的光泽），每个下面挂一块标签牌（英文 + 中文）。标签长的题（语法 / 发音小测、阅读题，最长 54 个字符）用**横幅靶**：一块宽墨板代替球，最多 3 块。
- **怎么玩**：点一下靶子（§6.1）→ 她转身、用手里的武器射过去 → 墨弹落到靶上那一刻才判（逻辑和画面一起，≤ 0.3 s）。摇杆照样能走、照样能用准星射。
- **复用**：武器和弹道是 `weapons.js` 的 `Projectiles`；命中用 `boss.js` 里现成的「射线对命中球」精确判断；炸开是 `fx.explosion` + `paint.flood`。

### M2 墨幕车道 `lane-curtain`（跑酷：选择题）

- **看起来**：她在自己的墨道上游（鱿鱼形态 `swimSpeed 11.8`，墨道在前面自动涂），前方墨道分成 2–4 条道，每条道尽头一道墨幕（副武器 `curtain` 的幕），幕上写选项。
- **怎么玩**：左右滑 = 换道，上滑 = 跳（`swimJumpVel`），下滑 = 潜（鱿鱼形态）。游进对的幕：幕炸成她的墨、加速一小段（借 `swimSpeed` 加成，不加新物理）；错的幕是珊瑚色的软墨幕，穿过去慢一下（`enemyInkDecel` 的手感，不掉血）。
- **读题时间**：题物在她前方 `D = 速度 × 提前量` 处出现，提前量 = 2.5 s + 每个字 0.06 s，封顶 6 s；题区里墨潮放慢到 0.6 倍（慢，不停）。
- **道够不够宽**：舞台的导航网格每格 1 m，只查过「能站人」，没有宽度。所以题行只放在**横向净宽 ≥ 道数 × 1.5 m** 的路线点上（沿路线法向在网格上扫，纯函数，Node 里用 `src/world/maps.js` 测）；不够宽就少一条道（最少 2 条）；2 条都放不下就往后挪到下一个够宽的点。
- **复用**：游泳、跳、潜、爬墙（墨道遇到能上的墙会涂上墙，她游上去——这就是跑酷）、超级跳的弧线（`special_leap`）当跳台；机器人是道具赛现成的 3 个对手。

### M3 节拍台 `beat-pads`（劲舞：听辨对子、音标）

- **看起来**：一块出生垫样的舞台，地上 2 块（听辨对子）或 4 块（音标「哪个词里有这个音」）发光台，台上写词；舞台随 `music.js` 的拍子脉动。
- **怎么玩**：这一题的词**提前一小节**放出来，下一小节的重拍上，跳到对的台上（2 块：点屏幕左 / 右半边或左右滑；4 块：点四个象限或四个方向滑）。踩准（窗口 ≥ ±150 ms，慢歌按 `0.35 × stepDur` 放宽）：`setDance` 一个小动作 + 加速；踩偏了但台对：照样算对，只是不跳舞。整小节没动 = 没答（§1 第 4 条）。
- **跑酷里**：同一题变成「拍子上换道」——道上的墨幕随拍子脉动，在重拍上穿过去有加成。
- **复用**：`music.js` 的 `bpm` / `stepDur` / `barDur` / `nextBarTime(after)`；舞蹈只用 `character.js` 现成的。拍子窗口是纯函数，Node 测；浏览器里用 `__inkwave.debug.freeze / step` 走拍子。

### M4 字弹 `type-shot`（打字射击：单词卡、听写句、写句）

- **看起来**：要打的东西是一个**字靶**——单词是一个带空格子的墨球（几个字母几个格），听写句是一条长长的墨船 / 墨墙（每个词一段），写句是出口区的写字墙（LEVELS 的 `write-wall`，墙上是中文，英文打上去）。字靶在她前方慢慢飘近，到一定距离就**停住等她**（没有倒计时）。
- **怎么玩**：屏幕下方一条**游戏自己的键盘**（不是系统键盘：iPhone 横屏时系统键盘会吃掉半屏，还会自动改字）。每按一个键，她射出一颗墨弹，在字靶的格子里写出那个字母——**中性灰墨，提交前不给对错**（§1 第 3 条）。⌫ 擦掉最后一颗墨。按「射」：整串字交给 `judge`——
  - 单词：对 = 字靶炸成她的墨；错 = 字靶变珊瑚色，旁边用她的墨写出正确拼写，「我的写法也对」照旧在（记 `S`）。
  - 听写句：`Host.dictScore` 的百分数 = 墨船炸掉的比例（≥ 80% 过，宿主的线），没对上的词留着、标出来。
  - 写句：`WT` 判关键形式，墙上她写的句子被墨涂上、缺的关键形式标出来。
  - 「提示」按钮：给音标 / 首字母（记 `H`，宿主的卡片同款）。
- **键盘**：26 个字母 + 空格 + `'` + `-` + ⌫ + 射；听写句和写句再加 `. , ?`（判分本来就不看标点和大小写）。竖屏占屏幕下方约 40%，横屏占下方约 45%、字靶框在上半；键宽照 iPhone 系统键盘（竖屏一行 10 个约 36 pt 宽），键高 ≥ 44 pt。
- **跑酷里**：「滑行段」——墨道变成一段自动转向的大弯，她不用管方向，专心打字射前面的浮标。
- **复用**：`Projectiles` 的弹道（一个键一颗，很短的射程）；字母用 CanvasTexture 贴在格子上；对 / 错的演出同 M1。

### M5 弱点 `weak-point`（Boss 周考）

- HULLBREAKER 现成的弱点挂上选项标签（L / R 两段的选择题）；W 段是 M4 打在船壳的装甲板上；S 段在甲板上的回声亭（M7）。Boss 出招只在她答完之后（LEVELS §2.5 照旧）。
- 复用 `boss.js` 的弱点、命中球、`G.boss.splash`。

### M6 展板路 `board-walk`（只看不答：课文、单词展板、语法讲解、阅读课文）

- 展板是舞台上的大牌子（CanvasTexture），沿着去门的路排开；她走（或自动走）到牌子前，相机弹簧过渡到「框住牌子」的位置，她不走就一直看着，往前走就继续——**这就是翻页**，没有「下一页」按钮。牌子区里没有任何东西会逼近她。
- 字太多的（第一课的开场白 200 字、阅读课文）：牌子上放标题和第一段，旁边一个「读全文」按钮打开**不暂停的阅读条**（下半屏、可滚动、世界照跑、她站着不动）；读完收起来往前走。它和题卡的区别：不在出题时出现、不挡题物、不停游戏。
- 单词展板（每 5 个词一块）上的「再听」「跟读」是牌子上的按钮，点了就放。

### M7 回声亭 `echo-booth`（口语，不计分）

- 一个亭子（出生垫 + 一块牌子）：问题、范例（中文）、句型、tip。她**站进亭子**，tts 读范例，她跟着说；**走出亭子** = 说完了（也可以点牌子上的「说完了」）。评分照旧等语音服务器（LEVELS §1.3）。

### M8 翻牌靶 `flip-target`（复习日 150 张，记 `F`）

- 一张张墨卡从地里翻起来，正面是中文；射一下，卡翻过去、放英文；然后卡两边各浮出一个靶：「认识」/「不熟」，射哪个就是自评（`store.recordFirst({ how: 'F' })`，G 已接）。「不熟」的当场变成 M4 的字靶打一遍（`T / H / S`）。

### 路标（打卡垫、周报牌、入门小测牌）

- 照 LEVELS：踩上打卡垫 = 这一天走完；周报牌、入门小测牌是牌子，「开经典页」是牌子上的按钮。不计分，不变。

## 5. 五种形式怎么变

### 5.1 解密闯关 `puzzle` → 走 + 射

- 门的位置、路线、自动走都照 B 的 `LearnFlow`。走到门前 `gateRadius`，题物在门前出现，相机弹簧过渡到「框住所有题物」的位置（§6.2），她还能动。一道门的条目一个接一个，门前就是一小段靶场 / 舞台。没有敌人、没有钟。

### 5.2 道具赛 `race` → 墨浪跑酷（形式 id 不改，中文名改「墨浪跑酷」）

- 路线照 `loopRoute`（出去一条道、回来一条道）。她和 3 个机器人在自己的墨道上游，自动向前；她只管换道、跳、潜。检查点 = 一行一行的题（M2 / M3），单词卡和听写句在「滑行段」（M4）。机器人照 `BOT_ANSWER` 掷骰（从来不看她的题），橡皮筋照旧。
- 道具照旧（`leap · rain · echo · shield · curtain · bomb · lane`），但都变成跑酷里的东西：墨幕挡住身后的机器人、墨弹定住最近的机器人、`lane` 是一段直通的墨轨、`leap` 是超级跳弧线、`rain` 是提示（记 `H`）。没有道具能跳过题（LEVELS 照旧）。
- 第二次答错不再「原地定住 `detour` 秒」（那就是定身）：改成**走远路**——墨道把她带进旁边一条绕远的支路，`detour` 秒后汇回主路。有盾就不绕。
- 「看板段」（课文、单词展板）在起跑前和检查点之间的直道上，用 M6 的牌子沿路排开；牌子区墨潮慢下来，机器人也慢下来（公平）。

### 5.3 对抗赛 `duel`（含今日小考）→ 区域里的靶场

- 区域照 INKWAVE 的 Zone Control 跑，机器人照打。题物浮在争夺中的区域上空（M1），第一个射中对的靶 = 这一题答对、区域涂一片（`duelFlood`）。她照样能打敌人；打敌人扫到的墨不算答题（§1 第 5 条）。字靶（M4）出现时她脚下自动铺一圈她的墨、敌人的子弹打不到她（小小的护盾，几秒），打完就撤——打字不该被偷袭。
- 小考 8 题照旧是一轮对抗赛。

### 5.4 Boss 战 `boss` → 弱点（M5），见 §3。

### 5.5 双人 `versus2` / `coop2` → 同样的题物，房主判

- 两边看到同样的题物；答案照旧是选项序号或一串字，走现在的消息（`versus2.js` / `coop2.js` / `duo.js`），房主判、先对者得。`coop2` 的「一个人拿线索、一个人作答」照旧：线索方听到 / 看到题，作答方的屏幕上才有可射的靶 / 键盘；两块墨垫照旧。

## 6. 手机输入和镜头

### 6.1 点射（触屏的主操作）

- 点屏幕：先在屏幕空间里找题物（每个题物投影的包围框外扩 16 px，有效热区 ≥ 44 pt），点中了 → 她转身（`aimFace*` 弹簧，不瞬转）、朝它开一枪；墨弹落到它身上才判。没点中题物 → 照 INKWAVE 原来的触屏（右半边看 / 射）。
- 纯函数 `pickTarget(screenX, screenY, projected[])`，Node 测（重叠时取最近的、边缘外扩、横幅的长方形）。

### 6.2 镜头框住题物

- 题物出现时，`cameraRig` 弹簧过渡到一个能让**所有题物都在安全区里**的位置：安全区 = 屏幕去掉顶上的题条、底下的键盘（M4 时）、两边 16 px。竖屏视野窄，题物排成 2 × 2 或竖着叠；横屏横着排。
- 纯函数 `layoutTargets(n, labels, aspect, safe)` → 每个题物的位置和大小，Node 测（竖 390 × 844、横 844 × 390、iPad 两个方向、标签 54 个字符的横幅）。

### 6.3 跑酷和节拍

- 左右滑换道、上滑跳、下滑潜；横屏时左拇指也可以用摇杆左右推。节拍台：两块时点左 / 右半屏，四块时点四个象限。所有手势的阈值放 `config.js` `TOUCH`。

### 6.4 键盘（M4）

- 见 §3 M4。键盘是游戏画的（DOM，一次建好，按键只改 class），不是系统键盘；不弹系统键盘、不自动改字、不自动大写。外接键盘照样能打（`input.js` 的按键）。

## 7. 画风和流畅（怎么保证和 INKWAVE 一样）

- **形状**：墨球 = 程序生成的二十面体细分球 + 现成的墨材质；横幅 = 圆角墨板；墨幕 = 副武器 `curtain` 的那块幕；台子 = 出生垫；墨船 / 写字墙 = 现成的门 / 墙网格拉长。没有新文件。
- **演出**：对 = `fx.explosion`（她的墨色）+ `paint.flood` + `EFFECTS` 里的声音和动作；错 = 珊瑚色淡入 + 门上的锁标（B 的八面体 `lock`）+ 柔的 `ui_back`；连对照 `EFFECTS` 的横幅和舞。
- **预算**（`quality=low`，iPhone）：一道活跃的门最多多出 12 个 draw call（同类题物用 `InstancedMesh`）；一道门一张标签图集（≤ 1024 × 512 的 CanvasTexture），在**前两道门**时就画好，门开后释放；题物用的材质在关卡加载时预热（`renderer.compileAsync`，照 `texlib.js` / `showcase.js` 现成的做法），游戏中不编译着色器；每帧不分配对象；题条和键盘只在换题时改 DOM。
- **量**：`main.js` 现在只有每半秒一个 `fps` 读数；第 1 期加一个只在 `__inkwave.debug` 下开的帧时间采样（记每帧毫秒数，给 p50 / p95），在同一个舞台上「门前出题」和「普通走路」比，p95 不差过 10%；真机看 TestFlight。

## 8. 横屏

- **游戏页两个方向都支持**。跑酷和节拍横屏更好玩：第一次进这两种玩法时提示一次「横过来更好玩」（不挡、能关、不再提示），竖屏照样全能玩。所有新版式（题条、题物排布、键盘）竖横各有一套，§10 两个方向都截图。
- **App（IELTS-Base 那边）**：现在 `Info.plist` 的 iPhone 只有竖屏。改成：App 其它页照旧锁竖屏，只有游戏页能转——App 的 delegate 实现 `supportedInterfaceOrientationsFor`，当 WebView 的地址是 `/game/index.html` 时返回 `.allButUpsideDown`，否则 `.portrait`；离开游戏页时用 `requestGeometryUpdate` 转回竖屏，并调 `setNeedsUpdateOfSupportedInterfaceOrientations`。`Info.plist` 的 iPhone 方向列表要不要同时加上横屏（有的系统版本只在列表里的方向里选），在第 7 期真机上核。
- **`touch.js`**：学习局两个方向都不出「请转屏」；`PORTRAIT_SCREENS` 和竖屏顶排偏移照旧；「`learn.hold` 时触屏不响应」这条随 `hold` 一起删掉。

## 9. 分期（一次只开一个子代理，一期一期来；每期结束都要绿）

每期结束的「绿」= `npm run check` 绿 + `npm run test:learn` 绿 + §10 的启动核查（这一期涉及的形式 × 竖横两个方向）+ 主会话看过截图。每期一个分支 `play-<n>`，合进 `claude/upbeat-newton-virpn1`；文档在 LEARN.md 记一节「play-n 交付」，DEVLOG 一条。

1. **内核 + 解谜里的选择题。** `LEARN.play` 开关；题物系统（`src/learn/play/`：题物的建立 / 释放、标签图集、`layoutTargets`、`pickTarget`、命中 → 选项序号）；题条；`puzzle` 在开关下不暂停、不定身；选择题（单词选义、语法 / 发音小测、阅读题）走 M1，其它条目暂时还走卡片（只在开关下、只到第 3 期）。纯函数的 Node 测试；启动核查改成「选择题门：没有面板、不暂停、题物在安全区里、点射能答、首答记一次」。
2. **字弹 M4。** 单词卡、听写句、写句在解谜里走 M4；游戏键盘竖横两套；提示 / 「我的写法也对」/ 百分数；回炉 M1 ↔ M4。测：提交前不泄露对错（截图 + 断言字母材质颜色不变）、证据方式和 §4 一致。
3. **节拍台 M3 + 展板路 M6 + 回声亭 M7 + 翻牌靶 M8 + 路标。** 做完解谜里一张卡片都没有。测：拍子窗口纯函数、整小节没动不写证据、踩偏照样算对。
4. **墨浪跑酷。** `race` 换成 §5.2：墨道、换道、跳、潜、爬墙、题行（净宽扫描纯函数）、滑行段、拍子上换道、机器人、道具、走远路。横屏提示。
5. **对抗赛 + 今日小考 + Boss。** §5.3、§5.4。
6. **双人联机赛、双人合作赛。** §5.5，两个客户端实测。
7. **横屏进 App**（IELTS-Base：delegate、`Info.plist`、`WebView.swift`；游戏这边 `touch.js` 竖横逐屏审）。
8. **删卡片。** 开关默认 `true`，卡片的代码路径删掉（留着要用的字符串）；LEVELS / LEARN 改到和本文一致；`design.test` 核每个条目有玩法；同步进 IELTS-Base、发 TestFlight。

**下一版 TestFlight 在第 8 期之后发**：业主说「下一版发布要改成这样」，所以哪种形式还有卡片就不发。

## 10. 验收

- **Node**（`npm run test:learn`）：`playOf` 覆盖三周每一个条目（§4）；`layoutTargets` / `pickTarget` / 车道净宽 / 拍子窗口 / 跑酷没答的判定；证据方式表（I3、I4、I5 的反例各一条：拍子踩偏不记错、溅射不算答、穿过空隙不写证据、提交前字母颜色不变）。
- **浏览器**（`flock -w 9000 /tmp/ielts-browser.lock nice -n 10`，一次一个）：IELTS-Base 那边的启动核查脚本改成新断言——每种形式 × 竖 390 × 844 / 横 844 × 390：走到第一道门、出题时**没有 `.iw-learn__panel`、`match.paused` 为假、`learn.hold` 为假**、题物都在安全区里、模拟一次点射 / 换道 / 打字能答、首答只记一次；截图给主会话看。
- **流畅**：§7 的帧时间对比；真机 TestFlight 上她玩一天的感受是最后一关。
