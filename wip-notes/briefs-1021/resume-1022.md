## 你是接手的那一个，先弄清楚前一个做到了哪
1. **读提交**：读一遍工作树的提交，它的提交说明写得很细，按顺序读一遍就知道做了什么。
   - inkwave：`git -C <工作树> log --reverse --format='%h %ad %s' --date=iso 088c6dd..HEAD`
   - IELTS-Base：`origin/main..HEAD`
2. **读没提交的改动**：`git status`、`git diff`（下面列了每条分支的）。读懂它想做什么：
   - 能完成的，完成、测过再提交；
   - 是不对的半成品，就 `git checkout -- <文件>` 丢掉。
   - 两种都写进汇报的 `decisions`。
3. **看临时目录**：它的临时目录 `…/scratchpad/<分支>/` 里可能有量具输出、日志、草稿，可以参考。截图照规矩，看完就删。
4. **对照任务书逐条核**：哪些做完了（有提交、有测试），哪些没做，哪些做了一半。

然后：
- 把剩下的做完。
- 最后把任务书要求的整套测试**重新跑一遍**。前一个跑过的不算数：它跑的是旧提交，而且没交回。
- 按原来的结构交回。汇报覆盖整条分支，不只是你这一段：前一个做的加上你做的。
- 任务书要你写的 LEARN 那一节（交付记录）还没写的，要写上。
